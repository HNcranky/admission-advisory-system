Chapter~\ref{chapter:Experiment} presented the system as a whole.
This chapter isolates its three principal contributions and examines each in the form problem, solution, and result.
The contributions are the conflict-aware consolidation of contradictory source data (Section~\ref{section:5.1}), the resilient inference gateway that keeps the assistant available under model failures (Section~\ref{section:5.2}), and the end-to-end ingestion of heterogeneous official sources including scanned documents (Section~\ref{section:5.3}).
Each addresses a gap identified in Chapter~\ref{chapter:Related_works} that existing admission tools leave open.

\section{Conflict-aware data consolidation}
\label{section:5.1}

\textbf{Problem.}
Official admission data is not only fragmented but internally inconsistent: two authoritative publications for the same program can state different quotas, and two sources can record different historical cutoff scores for the same program and year.
As established in Chapter~\ref{chapter:Related_works}, every existing channel resolves such disagreement silently --- it picks one value or shows none --- which hides exactly the uncertainty a student needs to know about before committing an application.
Consolidating these sources therefore cannot mean overwriting one value with another; the disagreement must survive into the recommendation.
The general problem of combining records that describe the same entity but disagree on attribute values is studied as \textit{data fusion}~\cite{bleiholder2009fusion}, which frames the available strategies as resolving, ignoring, or deferring a conflict; the design below applies the deferring strategy where a conflict cannot be settled objectively.
The related field of \textit{truth discovery}~\cite{li2016truth} estimates which of several conflicting values is correct by jointly inferring per-source reliability, and its central finding --- that no single source can be trusted unconditionally and that reliability must be inferred from evidence --- motivates the conservative stance taken here: the system resolves a disagreement only when an objective, auditable signal makes one value defensible, and otherwise defers rather than commits to a possibly wrong winner.

\textbf{Solution.}
Conflict awareness is built in three layers, and the detection-and-resolution logic is summarized in Algorithm~\ref{alg:conflict}.
At the storage layer, as described in Section~\ref{section:4.2}, the canonical tables are unique per source, so contradictory publications coexist as distinct rows rather than overwriting one another.
At the detection layer, the conflict service (\texttt{services/conflict/detection.py}) groups candidate records by program, year, and method --- the canonical conflict key built in \texttt{services/conflict/keys.py} --- and flags a conflict whenever the grouped rows carry two or more distinct values; quota and cutoff conflicts are detected separately because they have different keys and different resolution rules.
At the resolution layer, the two kinds of conflict are treated deliberately differently.
A quota conflict is settled by a deterministic comparison (\texttt{services/conflict/comparison.py}) that ranks the competing options on a fixed lexicographic ordering of trust level, then corroboration, then recency, then source confidence.
If that comparison is decisive --- the top option strictly outranks its nearest differing challenger on at least one axis --- the highest-ranked value is accepted; if every axis ties, the conflict is left unresolved rather than guessed, the field is marked uncertain, and every competing value is surfaced.
No language model is consulted at any point in conflict resolution; the agent (\texttt{agents/conflict\_agent.py}) wires only these deterministic comparators, which keeps the resolution fully auditable.
A cutoff conflict is never resolved by ranking alone either.
Instead, the system checks whether the disagreement is \textit{decision-changing} for this particular student --- that is, whether the competing cutoff values, classified through \texttt{services/cutoff/assessment.py}, would place the student's score into different fit categories.
If it is, the conflict is left unresolved, the affected field is marked uncertain, and the explanation presents every competing value; if it is not --- or if the student's score or method is not on a comparable scale --- the system references the most trusted value while still stating all of them.

\begin{algorithm}[H]
\caption{Conflict detection and resolution (per recommended program)}
\label{alg:conflict}
\KwIn{candidate records $R$ for a program; student score $s$ and method $m$}
\KwOut{a resolved value, or an uncertainty annotation listing all competing values}
Group $R$ by the conflict key $(\textit{program}, \textit{year}, \textit{method})$, separately for quota and cutoff fields\;
\ForEach{group $g$ with $\geq 2$ distinct quota values}{
  rank the options of $g$ by $(\textit{trust}, \textit{corroboration}, \textit{recency}, \textit{confidence})$, descending\;
  \eIf{top option strictly outranks its nearest differing challenger on some axis}{
    resolve quota to the top-ranked value\;
  }{
    mark quota \textbf{uncertain}; surface every competing value\;
  }
}
\ForEach{group $g$ with $\geq 2$ distinct cutoff scores}{
  order the options of $g$ by trust level (then score)\;
  \eIf{$s$ known \textbf{and} $m$ on a comparable scale}{
    $F \leftarrow \{\,\textsc{ClassifyFit}(s, v) : v \in \textit{values}(g)\,\}$\;
    \eIf{$|F| > 1$ \tcp*[r]{decision-changing}}{
      mark cutoff \textbf{uncertain}; list every competing value\;
    }{
      reference the most-trusted value; still list all values\;
    }
  }{
    reference the most-trusted value; still list all values\;
  }
}
\end{algorithm}

\textbf{Result.}
The pipeline surfaces conflicts instead of hiding them.
When a program's sources disagree in a way that matters, the recommendation marks the field as uncertain, lists the differing values, and advises the student to verify against the latest official announcement, which is the behavior required by edge case EC-16 and the conflict-disclosure use case of Chapter~\ref{chapter:Related_works}.
The conservative division of labor --- a fully deterministic comparison that resolves a quota conflict only when one value objectively outranks the others, and a decision-changing test that refuses to settle a cutoff conflict whenever the choice would alter the student's fit category --- keeps every consolidation auditable and defers, rather than guesses, exactly the cases where an over-confident commitment could mislead a student.
The conflict-handling edge cases (EC-16 and EC-17) are among the 17 satisfied cases reported in Section~\ref{section:4.4}.

\section{Resilient LLM inference gateway}
\label{section:5.2}

\textbf{Problem.}
The assistant depends on a hosted \gls{LLM} reached over the network, and that dependency fails in two distinct ways.
The first is a \textit{hard failure}: the \gls{API} is unreachable, unauthenticated, or rate-limited, which is common because the inference quota is finite and shared across every reasoning step.
The second is a \textit{soft failure}: the call succeeds but the body cannot be used --- the model wraps its \gls{JSON} in prose, emits malformed syntax, or returns a value outside the expected set.
A naive implementation that treats every \gls{LLM} call as reliable would let either failure crash a consultation, violating the graceful-degradation requirement NFR-01.
The two failure kinds also call for opposite responses: retrying a rate-limited endpoint is pointless, whereas retrying a malformed structured response can succeed.

\textbf{Solution.}
All model access is funneled through a single gateway (\texttt{services/inference/gateway.py}, Section~\ref{section:4.1}) that makes the two failure modes first-class; its control flow is given in Algorithm~\ref{alg:gateway}.
A hard failure is raised as an \texttt{InferenceError}; a soft failure is reported on the result as a \texttt{failure\_type} of \texttt{STRUCTURE\_FAILURE} rather than as an exception.
The gateway resolves a per-agent policy from a model registry (\texttt{services/inference/registry.py}) that supplies the primary model, an optional fallback model, a retry budget, and whether fallback is allowed for that agent.
It then treats the two failures differently: on a hard error it stops retrying the same model immediately and moves to the configured fallback model, because retrying an unreachable endpoint wastes time; on a structure failure it retries within the per-agent retry budget and then falls back to the secondary model.
If no fallback is configured, the gateway re-raises the hard error so that the call site can degrade, and every call site is written to do exactly that --- wrapping the call and substituting deterministic output on failure.
The clearest instance of this discipline is intent classification.
When the gateway is unavailable or returns an unusable response, the router falls back to a deterministic keyword classifier that mirrors the prompt's own priority rules: it checks knowledge-topic keywords before advisory phrases, so a factual question is never misrouted into a full advisory run while the model is unavailable, and unrecognized messages become a clarification request rather than a silent re-run.
This deterministic fallback was introduced in commit \texttt{c2ef582}.

\begin{algorithm}[H]
\caption{Inference gateway: hard- vs structure-failure handling}
\label{alg:gateway}
\KwIn{request $q$ with an agent name}
\KwOut{a usable \texttt{InferenceResult}, or a raised \texttt{InferenceError} for the call site to handle}
$p \leftarrow$ registry policy for $q$'s agent \tcp*[r]{primary, fallback, retries, allow\_fallback}
$e \leftarrow \varnothing$ \tcp*[r]{remembered hard error}
\For{$\text{attempt} \leftarrow 0$ \KwTo $p.\textit{maxRetries}$}{
  $r \leftarrow \textsc{Generate}(q, p.\textit{primaryModel})$\;
  \If{\textsc{Generate} raised \texttt{InferenceError} $\varepsilon$ \tcp*[r]{hard: network/auth/rate-limit}}{
    $e \leftarrow \varepsilon$; record \textsc{ApiError}; \textbf{break} \tcp*[r]{stop retrying this model}
  }
  record $r.\textit{failureType}$\;
  \lIf{$r.\textit{failureType} \neq \textsc{StructureFailure}$}{\Return $r$}
}
\eIf{$p.\textit{allowFallback}$ \textbf{and} $p.\textit{fallbackModel}$ exists}{
  $r \leftarrow \textsc{Generate}(q, p.\textit{fallbackModel})$ \tcp*[r]{re-raises on hard error}
  \Return $r$\;
}{
  \lIf{$e \neq \varnothing$}{\textbf{raise} $e$ \tcp*[r]{let the call site degrade}}
  \Return $r$ \tcp*[r]{last structure-failure result}
}
\end{algorithm}

\textbf{Result.}
The assistant remains usable through model outages.
Intent routing continues to function without any model call, knowledge answering degrades to an honest ``no data'' reply rather than a fabricated one, and structured-output hiccups are absorbed by retry and fallback instead of surfacing as crashes.
Concentrating this logic in one gateway means every reasoning step in the system --- routing, conflict tie-breaking, knowledge answering, and \gls{OCR} --- inherits the same resilience without re-implementing it, and the per-stage telemetry records when a fallback or a structure failure occurred, so an outage is visible to operators rather than silent.

\section{End-to-end ingestion of heterogeneous official sources}
\label{section:5.3}

\textbf{Problem.}
The data that makes the assistant useful lives in sources that share no common format: each university structures its admission pages differently, proposal documents are published as \gls{PDF}s, and some of those \gls{PDF}s are scanned images with no text layer at all.
A pipeline that assumes uniform, machine-readable input cannot ingest this material, yet without it the canonical store and the knowledge corpus would be empty.
Scanned documents are the hardest case, because recovering their text requires \gls{OCR}, and model-based \gls{OCR} introduces a failure mode of its own.

\textbf{Solution.}
Ingestion is a configurable, staged pipeline (Section~\ref{section:4.1}): per-source configuration selects the fetch strategy, the document router predicts each document's type, and a matching parser and extractor turn it into raw facts that are then normalized against per-school dictionaries into canonical records.
Because the per-source configuration and dictionaries are data rather than code, adding a school is largely a matter of configuration.
Scanned \gls{PDF}s are handled by a hybrid per-page extractor (\texttt{ingestion/knowledge/pdf\_ocr.py}, Section~\ref{section:3.4}), whose logic is given in Algorithm~\ref{alg:ocr}: a page whose stripped text layer is at least 50 characters long is read directly, and only shorter (effectively image-only) pages are rendered to PNG at roughly 200 \gls{DPI} and sent to the multimodal gateway for transcription, keeping cost proportional to the number of scanned pages.
The distinctive part is the safeguard against model \gls{OCR} repetition loops, introduced in commit \texttt{b41dd9f}.
When transcribing a page with merged table cells, the model can lock into emitting one character endlessly --- one NEU page produced on the order of a million dash characters.
The extractor classifies an output as \textit{degenerate} when it exceeds an absolute ceiling of 20{,}000 characters per page, or when --- among at least 2{,}000 non-whitespace characters --- a single character accounts for more than 80\% of them.
A degenerate page is retried once at a raised decoding temperature (0.3, up from 0.0) to break the greedy loop; if it is still degenerate the page is marked failed and the remaining pages of the document are ingested normally, so one bad page cannot discard a whole document, while a document that yields no text at all is deliberately left un-ingested rather than recorded as empty.

\begin{algorithm}[H]
\caption{Hybrid per-page extraction with degenerate-OCR detection}
\label{alg:ocr}
\KwIn{a scanned or mixed \gls{PDF}}
\KwOut{per-page text, each tagged \texttt{text\_layer}, \texttt{ocr}, or \texttt{failed}}
\ForEach{page in document}{
  $b \leftarrow$ stripped pdfplumber text layer of the page\;
  \lIf{$|b| \geq 50$}{record $(b, \texttt{text\_layer})$; \textbf{continue}}
  $\textit{img} \leftarrow$ render the page to PNG at $\approx 200$ \gls{DPI}\;
  \For{$\tau \in (0.0,\ 0.3)$ \tcp*[r]{retry once at raised temperature}}{
    $t \leftarrow \textsc{GatewayOCR}(\textit{img},\ \tau)$\;
    \lIf{\textbf{not} \textsc{Degenerate}$(t)$}{record $(t, \texttt{ocr})$; \textbf{continue to next page}}
  }
  record $(\texttt{""}, \texttt{failed})$ \tcp*[r]{both attempts degenerate}
}
\lIf{every page is empty}{\textbf{raise} --- leave the document un-ingested}
\BlankLine
\SetKwProg{Fn}{Function}{:}{}
\Fn{\textsc{Degenerate}$(t)$}{
  \lIf{$|t| > 20000$}{\Return true}
  $c \leftarrow t$ with all whitespace removed\;
  \lIf{$|c| \geq 2000$ \textbf{and} $\max_x \text{count}(x, c) / |c| > 0.8$}{\Return true}
  \Return false\;
}
\end{algorithm}

\textbf{Result.}
The pipeline ingests both structured and unstructured official sources end to end.

The canonical store holds 136 admission records and 699 cutoff records for HUST and 20 admission records and 16 cutoff records for VNU-UET, and the knowledge corpus holds 18 documents and 406 chunks drawn from HUST, NEU, VNU-UET, and national \gls{MOET} regulations, as reported in Section~\ref{section:4.3}.
The degenerate-output safeguard is what makes the scanned subset of that corpus ingestible: without it, a single repetition-loop page would either bloat the store with megabytes of junk or abort the document; with it, the bad page is isolated and the rest of the document is preserved.

This chapter examined the system's three contributions in depth: conflict-aware consolidation that preserves and discloses contradictory source data, a resilient inference gateway that distinguishes hard from soft model failures and keeps the assistant available through both, and an end-to-end ingestion pipeline that handles heterogeneous and scanned official sources with an explicit safeguard against model \gls{OCR} failure.
Together these address the three gaps --- unreconciled data, unreliable model dependence, and inaccessible source formats --- that Chapter~\ref{chapter:Related_works} identified in existing admission tools.
Chapter~\ref{chapter:conclusion} concludes the thesis and sets out the remaining work.
